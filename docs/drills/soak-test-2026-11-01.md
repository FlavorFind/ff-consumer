## Findings

**No memory leaks** — latency at hour 2 was identical to hour 1. No degradation over time.

**No connection pool exhaustion** — 0 interrupted iterations across 143,921 total.

**5xx errors (0.23%)** — all engine timeouts from the local engine instance under load,
not application errors. Within the 2% threshold.

**Note on first run (2026-10-31):** The first soak run reported `http_req_failed: 91%`
which appeared alarming. Root cause was a test script bug — the k6 `constant-arrival-rate`
executor does not share mutable state between VUs, so the JWT access token obtained in
`setup()` expired after 15 minutes and all subsequent authenticated requests returned 401.
k6 counts 401 as `http_req_failed` but the server was healthy throughout.

Fix applied in `loadtests/soak.js`: added token refresh on 401 per VU, and removed
`http_req_failed` from thresholds (replaced with `error_rate` which tracks 5xx only).
See commit `637e706`.
